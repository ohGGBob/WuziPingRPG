# 天工

**当前整合版本为 0.3.18（versionCode 58）**，以 `studio/build.gradle` 为准。首页版本号和 `tools/verify-studio-release.py` 都读这个版本，不再把 0.2.7（versionCode 39）当成当前包。下方 0.1.x / 0.2.x 是历史记录。

一个可安装的 Android 手机工作台原型。打开后先停在首页：常用的是写 Python、记事本和 AI 助手，上课、英文朗读和《伍子平 · 星火远征》放在下面。点一下卡片就进入，不用再滑一轮再点确认。Python 离线运行。不是微软 VS Code 的移植，界面使用 CodeMirror 6，Python 使用随 APK 打包的 Pyodide 0.27.7 / CPython 3.12.7。首页标着当前版本。

## 首页和返回（0.2.1）

首页是根。功能按三组排列：

| 分组 | 功能 | 类型 |
|---|---|---|
| 学习 | 上课、英文朗读、扫描文档 | 扫描是原生页面（需要 Android 10+ 和相机） |
| 创作 | 写 Python、记事本、修图 | 修图是原生页面，内核来自浮生图梦 |
| 助手与休息 | AI 助手、星火远征 | 网页模块 |

顶部的「接着做」卡片指向上次打开的功能，未保存的原文件会在卡片上点出来。各模块左上角都有「‹ 首页」（扫描页是「‹」，修图页是「‹ 天工」），作用和系统返回键回到首页一致。

返回键一次只关一层，顺序固定：对话框 → 文件抽屉 → 画画 → 查找 → 模块自己的子层（AI 设置面板、上课里的时间轴或 PPT、编辑器里的游戏页）→ 首页 → 询问要不要退出。在首页再按一次会问要不要退出，不会掉回刚才的编辑器。键盘弹着的时候，第一次返回只收起键盘。修图页里返回先退出裁剪、再收起展开的面板，最后回到天工首页；扫描页按返回直接回首页，拍好的页面留在扫描模块里。

实现上，模块表和返回路由都在 `web/src/back.js`：`MODULES` 登记每个功能（`kind: 'web' | 'native'`），`resolveBack` 决定这一步该关哪一层。页面里额外的子层登记在 `app.js` 的 `MODULE_LAYERS`。原生模块由页面发 `openModule {id}`，`EditorActivity` 拉起对应 Activity，回来时在 `onResume` 发 `moduleReturned {id}`；启动后宿主还会发 `capabilities`（是否能扫描、系统版本），首页据此标出不可用的功能。加新功能时在 `MODULES` 加一行，网页模块实现 `applyMode` 分支，原生模块在 `EditorActivity.openModule` 加一个分支。

草稿在离开页面时会先写入本机工作区。还没点「保存」的手机原文件会在首页的继续卡片和退出说明里点出来，退出不会把这些修改丢掉，也不会偷偷写回原文件。正在录音时不能直接换到别的模式；正在跑代码时也不能换到记事本、AI 或原生模块。WebView 自己的历史记录不参与返回，避免把整个工作区页面卸掉。

### 构建含扫描模块的包

`scan/` 是 Kotlin 库模块，依赖 AndroidX CameraX 1.3.4 和 ML Kit 离线中文识别 16.0.0，只能经 Gradle 编译：

```bash
gradle :studio:assembleDebug        # 产物 studio/build/outputs/apk/debug/studio-debug.apk
gradle :scan:regressionCheck        # 扫描模块的 39 项 JVM 回归
```

扫描模块把 OCR 模型打进包里，Gradle 打出的调试包约 65MB；不含扫描模块的手工构建包约 16MB。`tools/build-studio.sh` / `.ps1` 直接调用 javac、d8 和 aapt2，不编译 Kotlin，打出的包没有扫描页面；首页会显示「扫描文档」不可用，其他功能照常。修图页的网页资源由 `web/build-photo.mjs` 打包，`npm run build` 会一起执行，需要 WebView / Chrome 89 及以上。

## AI 助手（第六个模式）

联网**默认关闭**。开启后填写 DeepSeek 兼容接口地址、API Key 与模型，请求由 Android 原生 HTTP 桥发出（WebView 的 CSP 禁止外部 `connect`），密钥只保存在工作区 `state.ai`，不写日志。浏览器预览不能访问外部服务，会明确提示在 APK 中使用。

界面与能力：流式对话、模型/温度/系统提示设置、生成中插话排队与「立即发送」、工具过程折叠、会话导出与回放、Canvas 分享卡、六套主题、中英切换、对话/网页双视图、横屏平板布局，以及一只随状态变化的原创像素小助手。

工具卡协议是本项目自研的：AI 在回复里输出 ` ```tool ` 代码块，页面渲染成卡片等你点「允许」。只读工具（读文件、列文件、离线运行代码、设备状态）可设为自动批准；写工具、分享、短信草稿、剪贴板和已安装应用列表必须人工确认。勾选「多步执行」后，一次提问可以连续走多步：模型先调用工具，结果写回对话，再决定下一步，最多 6 步。点「停止」或离开 AI 模式会中断这一轮；生成过程中插进来的话会等这一轮走完，「立即发送」会打断并先发那一句。敏感步骤仍然停在卡片上，不会自己往下冲。

设备工具卡（0.1.17 新增）：

| 工具 | 行为 |
| --- | --- |
| `authorizeTree` / `scanFiles` | 用系统文件选择器授权目录；**只读**枚举，输出路径、大小、修改时间与判定理由 |
| `organizeFiles` | 按确认后的方案重命名，每批最多 10 项 |
| `deleteFiles` | **永久删除**，见下方红线 |
| `writeWorkLog` | 把 AI 整理出的摘要写入工作日志草稿 |
| `scheduleTask` / `listTasks` / `cancelTask` | 创建提醒、定时日志、定时扫描报告；支持开机恢复 |

**⚠️ 删除不可逆。** Android 没有统一回收站。第一遍扫描永远只读；删除前必须在应用内二次确认并逐条列出路径，每批 ≤10，只作用于你主动授权的系统目录，删除结果写入操作日志。定时任务**永不执行删除**，也**不会**代发短信、分享或打开其他应用。开机自启与精确闹钟权限（`RECEIVE_BOOT_COMPLETED` / `SCHEDULE_EXACT_ALARM`）由你在系统设置里手动授予，厂商省电策略仍可能拦截后台触发。

### 手机操作

助手可以提议这些动作。除了「查看设备状态」和「查看通知权限」以外，每一项都要在卡片上点「允许」才会执行；读取剪贴板和列出已安装应用即使勾了「自动批准只读工具」也不会自己跑。

| 工具 | 行为 |
| --- | --- |
| `deviceContext` | 电量、是否充电、网络（wifi / cellular / none）、语言、数据分区剩余空间、本应用通知开关。网络读取用普通权限 `ACCESS_NETWORK_STATE`，不弹运行时授权框 |
| `notificationStatus` | 只看本应用的通知是否被系统关掉 |
| `listApps` | 最多 60 个可启动应用的名称和包名，需允许 |
| `openUrl` | 只打开 `http` / `https`。`javascript:`、`file:`、`intent:` 和带账号密码的链接会被拒绝 |
| `dial` | 打开系统拨号盘并填入号码，**不会拨出**，也不申请 `CALL_PHONE` |
| `draftSms` | 打开短信应用里的草稿，**不会发送**，也不申请 `SEND_SMS`。定时任务不能调用它 |
| `shareText` | 打开系统分享面板，由你再选目标应用，内容不会静默送出 |
| `openMaps` | 用 `geo:` 打开地图，可以给地点文字或经纬度 |
| `openSettings` | 只打开白名单里的系统页：`wifi`、`bluetooth`、`location`、`apps`、`battery`、`notifications`、`accessibility`、`display`、`sound`、`wireless`。助手不会在设置里自动点按 |
| `openApp` | 按包名或应用名称打开一个可启动的应用；重名时只列出候选，不猜测 |
| `readClipboard` / `writeClipboard` | 读取或写入纯文本。读取视为隐私操作，必须点允许；单次最多约 4000 字 |

Android 11 及以后，清单里的 `<queries>` 只声明启动器、浏览器、拨号、短信草稿、地图和文本分享，用来解析「这台手机有没有对应应用」。没有 `QUERY_ALL_PACKAGES`。

**无障碍没有做进这一版。** 没有 `AccessibilityService`，助手不能点击、滚动、输入或截取其他应用的界面树。`deviceContext` 会明确写「未安装」。若要自己去系统里开关无障碍，可以让助手打开 `openSettings` 的 `accessibility` 页，开关仍由你手动拨。以后如果要做，必须保持可选、在系统设置里由你启用，并且每一次点击单独批准；定时任务也不能获得这项能力。

这些权限写在源码清单里，**版本号仍是 0.1.17**，仓库里的安装包没有重打。`ACCESS_NETWORK_STATE` 是安装时授予的普通权限，要等下次本地构建才会进手机；已经装上的 0.1.17 包没有这一项，设备状态里的网络会显示 `unknown`，其余动作不受影响。

在手机上试：进入「AI 助手」，开启联网并填写接口，勾上「多步执行」。可以先点「看看手机状态」，或直接说「电量低的话打开省电设置」。只读状态在勾了自动批准时会自己跑；打开设置前会停在卡片上。短信类请求应停在「打开短信草稿」，发送按钮仍在系统短信应用里。

离线执行沙盒复用随包 Pyodide / JS Worker：AI 生成的代码在本机跑完，输出回灌对话，不需要 1GB 的 Linux 运行时，也不需要额外权限。

## 上课模式（录音 · 笔记 · 时间轴）

录音启动失败时会先释放已占用的麦克风、逐级回退录音约束（高级降噪 → 纯 `audio:true`），再允许点「重试」；错误原因只显示在录音条下方，不再重复弹提示。「麦克风暂时无法启动」不等于一定被其它应用占用，也可能是系统音频服务未就绪。

拍 PPT 投屏/屏幕时容易出现的彩色摩尔纹，现在导入照片时会自动抑制：PPT 面板的「拍后去摩尔纹」开关默认开启，强度可调 0–100%。实现只压缩色度通道的异常高频块、保留亮度，所以黑白文字保持锐利；处理后还会做一次轻微重采样打散残余周期条纹。预览大图时可点「对比原图」切换。这是**拍后即时处理**（约 0.1–0.5 秒），不是取景器逐帧实时，也不需要 `CAMERA` 权限；对新导入的照片生效，原图对比数据只存内存、不进工作区快照。

课堂三件事一次完成：录音、记笔记、拍或导入 PPT，三者按时间轴自动对齐；复习时点任意一行笔记，音频跳到对应位置并显示当时的 PPT 页。全程离线。

- **录音**：WebView `getUserMedia` + `MediaRecorder`（webm/opus 16kbps），开始 / 暂停 / 继续 / 停止，2 小时上限自动停止；Android 侧为 `RECORD_AUDIO` 危险权限，首次点击录音时经 `WebChromeClient.onPermissionRequest` 运行时授权，拒绝后有引导提示。
- **自动锚点（能量 VAD）**：每 500ms 采样 RMS，动态阈值（10 秒滚动平均 × 1.5，含 0.012 绝对下限）；语音段超过 1s 在段中点记 `speech` 锚点，语音结束后沉默超过 3s 在沉默起点记 `silence` 锚点。录音中随时可点「📌 标记锚点」生成 `manual` 锚点，并自动关联最近一张未标记的 PPT 照片。
- **时间戳笔记**：上课模式的笔记写在 `课堂笔记.md`；录音期间新建的每一行通过 CodeMirror StateField 记录创建时刻，在行首 gutter 显示 `MM:SS` / `HH:MM:SS` 徽章，编辑（插入、删除、换行合并）时随文档自动重映射。
- **同步回放**：点击笔记行或时间戳徽章 → 音频跳到对应时刻并播放；播放中当前笔记行高亮（行背景 + 徽章点亮）。时间轴 Canvas 绘制 RMS 波形包络、三类彩色锚点与红色播放头，支持点击定位与围绕播放头的窗口缩放（×1–×32）。
- **PPT 照片**：拍照或从相册导入，最长边压缩到 1024px（JPEG 0.8），最多 50 张；点缩略图放大预览，点时间标签跳到该页开始时刻；锚点可编辑标签 / 时间（支持 `1:23` 写法）或删除。Android 上走原生相册选择器：原图先复制到应用缓存目录，页面再按同源 URL 读入并压缩，不经过 WebView 的 `content://`，也不再把照片塞进 `evaluateJavascript`。
- **整个 PPT 文件**：除拍照外还能直接导入 `.pptx`。`pptx.js` 用 JSZip 解开包体（PPTX 就是 ZIP），读 `presentation.xml` 拿页序与页面尺寸，逐页解析 `slideN.xml`：文本框（字号 / 加粗 / 颜色 / 对齐 / 自动换行 / 垂直居中）、图片（`p:pic` + 关系表定位）、表格与组合形状都画到 Canvas 上，再按 1024px 宽转成 JPEG 进入同一个照片库，因此锚点、时间轴、预览这些能力完全复用。占位符（`p:ph`，如「标题和内容」版式）不在 slide 里写坐标时，会从 `slideLayout` 继承位置和大小，布局也没有再退回 `slideMaster`。填充与描边只看 `spPr` / `a:ln` 的直接子节点：没有声明填充的形状不会被涂色（避免「只有红边框」变成一整块红）。主题色从 `theme1.xml` 读取。旧版二进制 `.ppt`、WMF/EMF 图元、图表会降级或跳过，并在提示里说明。原生只负责把文件复制进缓存（只读、不取持久授权），页面用同源 URL 读取，同样不走 base64。
- **存储**：音频 base64、波形包络（0.5s 间距 RMS 序列）、锚点、照片与笔记时间戳全部保存在工作区 JSON（`state.lecture`），随草稿自动保存 / 恢复；宿主侧沿用 32MB 快照上限，2 小时录音约 19MB，超出建议及时整理。

前端实现：`studio/web/src/audio-engine.js`（录制 + VAD + 播放）、`timeline.js`（Canvas 时间轴）、`lecture.js`（模式逻辑 + CodeMirror 扩展）、`lecture.css`（三栏布局）；启动页第四个选项、录音控制栏与移动端「笔记 / 时间轴 / PPT」底部 Tab 见 `index.html`。录音时长上限、锚点检测参数与存储预算集中在 `audio-engine.js` 顶部常量。

## 笔记模板与笔记出题（反馈版）

右上角「⋯」操作菜单新增两项：**笔记模板**和**笔记出题**。两者都沿用现有 `<dialog>`，系统返回键先关对话框，不会把编辑器卸掉。

**笔记模板**（`studio/web/src/note-templates.js`）：提供空白、康奈尔、大纲、错题整理四种 Markdown 模板。可以选择「新建模板笔记」创建独立文件，或「插入当前笔记」放到光标/选区处；文件名冲突自动编号（`康奈尔笔记.md` → `康奈尔笔记-2.md` → `-3`），没有覆盖逻辑。上次选中的模板保存在工作区 `state.noteTemplates.last`，读取旧工作区时会清洗，名字不认识就回到空白模板。普通记事本和 Python 模式创建后会直接打开新文件，之后可在文件抽屉重新打开。

进入记事本时优先恢复当前 `active` 的 `.md` / `.txt` 文件；刷新后如果 resume card 指向 `康奈尔笔记.md` 这类模板笔记，会直接打开它。当前文件不是笔记时，尝试本次会话最近打开的笔记，最后才回退到 `笔记.txt`。`课堂笔记.md` 固定归上课模式，不会成为普通记事本目标；模板笔记也不会写进 `lastCodePath`，从 `main.py` 进入模板/记事本后，返回 Python 仍打开原来的代码文件。

课堂笔记仍是固定的 `课堂笔记.md`。正在录音或已有时间戳时，「插入当前笔记」会被禁用并提示改用新建；「新建模板笔记」只创建另一份文件，不切换当前课堂笔记，也不清空时间戳。时间戳计数由 `lecture.js` 的 `lectureStampCount()` 从当前编辑器、切走前的编辑器快照或工作区快照三处读取。

## 0.1.22 更新

三处真机问题，都跟「页面和宿主各写一套」有关：

- **「停止并保存后退出」可能丢录音**：停止录音后 `engine` 立刻置空，而编码/写文件/刷新回放还在后面的 await 链里；宿主的退出轮询只问 `busy()`，一看 `engine` 空了就 flush（此时 `audio` 还是空）并销毁 WebView。现在停止后的整段落盘都计入 `busy()`（`settling` 计数），宿主必须等音频真正写进草稿才继续退出；等待上限从 9 秒放宽到 20 秒。
- **返回键在真机上是死代码**：宿主 `onBackPressed` 里内联了一串 DOM 判断，从不调用页面里的 `window.Studio.back()`。现在宿主只调 `window.Studio.back()`。页面仍返回布尔值：`true` 表示这一层已经处理，`false` 表示要退出。退出时如果课堂还在录音或落盘，宿主先问「停止并保存后退出」，等 `lecture.busy()` 变成 false 再 flush。层级仍是文首的首页规则：弹窗、抽屉、画画、查找、上课子页，然后才回首页；首页再按一次才退出。从首页打开的游戏回到首页，编辑器里的游戏标签回到刚才的文件。键盘弹着时第一次返回只收起键盘。
- **录音不再整段 base64 过桥**：以前停止时把 2 小时音频（约 19 MB）整段转 base64，JS 的 `JSON.stringify` 与 Java 的 `new JSONObject` 都在主线程上；检查点还每 45 秒把全量重写一次，超时就退回内嵌、直接撞 30 MB 快照上限。现在录音期间每秒的分片（约 2–6 KB）直接经 `audioBegin/audioChunk/audioEnd` 追加进同一个文件，宿主边收边写、每片 flush；停止时只要关流拿回文件名。检查点也从「重写音频」变成「只记时长与波形」，间隔缩到 15 秒，进程被杀最多丢最后一片。

## 0.1.18 更新

- 修掉真机上「后台没有别的应用，却提示麦克风被其他应用占用」的根因。提示文字来自 `NotReadableError` 的旧映射，而 Android WebView 报这个错其实多半与别的应用无关：
  - `AndroidManifest.xml` 缺 `MODIFY_AUDIO_SETTINGS`：WebView 的采集由 Chromium 的 AudioRecord 实现，初始化时要调整音频参数，缺这条普通权限时系统音频服务直接拒绝分配麦克风，页面侧只能收到 `NotReadableError`。已补上，并加了 `uses-feature microphone(required=false)`。
  - 授权顺序反了：原来要等 WebView 的 `onPermissionRequest` 回调里才弹系统权限框，用户点完「允许」再 `grant()` 时音频源往往已经初始化失败。现在页面在调 `getUserMedia` **之前**先通过 `micPermission` 消息在原生层拿到 `RECORD_AUDIO`（新增请求码 `MIC_WARM`），WebView 授权时权限已就绪。
  - 只授予音频采集资源：`grant()` 不再把页面请求的其它资源（如摄像头）一并放行，避免 Chromium 去开不存在的设备导致整条采集链路失败。
- 修掉「自己占住麦克风」的泄漏：`AudioEngine.start()` 在拿到流之后任何一步抛错（`MediaRecorder`/`AudioContext` 构造失败等）都不会停轨道，流对象被丢弃但麦克风仍被本进程打开，用户点「重试」只会继续看到"被占用"。新增 `abortStart()` / `stopStream()`，所有失败与停止路径都会真正释放；录音失败后无需重启应用即可重新开录。
- `NotReadableError` 不再直接判死刑：改为三轮退避重试（0 / 250 / 700 ms，每轮带降噪约束与 `audio:true` 两个档位），这类错误在 WebView 上常是音频服务尚未释放的瞬时状态。
- 错误提示改成实情并带诊断信息：不再让用户去关别的应用，改为「系统没有把麦克风交给页面（NotReadableError）」，提示条附上错误名与系统暴露的麦克风输入数量（枚举带 800 ms 上限，避免个别 WebView 挂死）。
- 版本号 0.1.18（versionCode 26）。

## 使用方法

首次启动先选择「写 Python」「普通记事本」或「游戏」。选 Python 后工作区有 `main.py`、`geometry.py`、`data.json` 和 `index.html` 示例；默认标准输入是「伍子平」，直接点击运行可看到真实 Python 输出。想换模式时，点右上角「⋯」→「切换模式」。

1. 点击左上角文件按钮，打开文件或导入项目文件夹。
2. 选中要运行的 `.py` 入口文件。运行时工作目录设为入口文件所在目录；同目录模块和数据可使用相对路径。
3. 有 `input()` 的程序先在「标准输入」填写，每行对应一项；内容用完后返回 EOF，不会无限等候。
4. 点击运行，查看输出、报错。运行期间文件只读，可立即停止；停止后继续编辑。
5. 草稿自动保留。点击保存才会写回已授权的原文件；新文件先选择手机上的保存位置。

桌面键盘支持 Ctrl+S 保存、Ctrl+Shift+S 另存、Ctrl+F 查找替换、Ctrl+Enter / F5 运行、Ctrl+O 打开、Ctrl+N 新建。

## 当前范围

Python 是 WebAssembly 环境，支持常用标准库，不是手机系统级 CPython 或完整终端。没有 pip 安装、任意本机扩展包、系统 shell、VS Code 插件、LSP、Git 面板或调试断点。工作区传入运行环境的文本统一为 UTF-8。程序正常结束或报错时回收新增/修改的 UTF-8 文本文件；强制停止不回收未完成的文件变化，文件删除仅作用于本次运行。

单个导入文件最多 2 MB，工作区最多 160 个文件，一次导入最多 12 MB，目录深度最多 10 层；缓存目录和二进制文件跳过并提示。不是 PDF、Office 文档或所有二进制格式的查看器。项目中的图片附件暂不导入。

运行资源全部在 APK 内，代码无需上传服务器。应用的 INTERNET 权限用于只监听 `127.0.0.1` 的本机资源服务；编辑器与预览使用不同页面，预览没有原生文件接口，运行线程也没有原生文件接口。界面与工作区草稿通过受控消息连接到 Android。预览默认阻止外部网络请求。

## 构建

```powershell
# 已检入离线 Web bundle 和 Python 运行文件时，不需要 npm 或网络
.\tools\build-studio.ps1 -SkipWebBuild
.\tools\build-studio.ps1 -SkipWebBuild -ParallelInstall

# 修改编辑器前端后
npm --prefix studio/web ci --no-audit --no-fund
npm --prefix studio/web run build
.\tools\build-studio.ps1 -SkipWebBuild

.\tools\verify-studio.ps1
python .\tools\verify-studio-release.py
python .\tools\package-studio-source.py
```

```bash
# Linux：JDK 17，ANDROID_HOME 指向含 platforms/android-34 与 build-tools/34.0.0 的 SDK
npm --prefix studio/web ci --no-audit --no-fund
npm --prefix studio/web run build
./tools/build-studio.sh --skip-web-build
./tools/build-studio.sh --skip-web-build --parallel
./tools/verify-studio.sh
```

两个脚本现在写出 `dist/Ember-Studio-0.1.17.apk` 和 `dist/Ember-Studio-0.1.17-parallel.apk`（versionName 0.1.17、versionCode 25）。仓库里已经提交的安装包仍是 0.1.15，这次合并没有替换它们。需要 JDK 17、Android SDK Platform 34 / Build Tools 34.0.0。构建默认复用 `build/manual/debug.keystore`，也可通过 `-SigningKey` 或 `--signing-key` 指向自己的 Android 调试密钥。私钥不进入 Git 或源码压缩包。仓库里的 0.1.15 包用的是原来的开发证书，可以覆盖 0.1.13 / 0.1.14。换一把新密钥打出来的包不能覆盖旧签名应用。构建在 `zipalign` 和签名前调用 `tools/normalize-apk-assets.py`，修正 Windows 版 aapt2 写入 ZIP 的反斜杠资源名；`verify-studio-release.py` 同时检查原始条目名，不能用 Python 读取时的自动转换来代替。它要求两个包的证书 SHA-256 都是 `0dcafc3b079966a52c69d8292d86078717e42bdc2883485e335aebf0214d5aca`，对不上就失败。首次重新获取 Python 文件使用 `tools/fetch-python-runtime.ps1`，许可证使用 `tools/fetch-studio-licenses.ps1`。

前端源文件在 `studio/web/src`，Android 宿主在 `studio/src/main/java`。`app` 仍可独立构建原游戏；`studio` 复用原游戏 Java 代码与素材，未替换已有 0.7 安装包。原生入口仅在带 `editorHost` 参数时显示返回编辑器选项。

运行环境来源：[Pyodide 固定版本部署文档](https://pyodide.org/en/0.27.7/usage/downloading-and-deploying.html)、[Worker 执行文档](https://pyodide.org/en/0.27.7/usage/webworker.html)。第三方许可证和上游源代码地址随 APK 收录在 `assets/studio/licenses/`；npm 精确依赖在 `studio/web/package-lock.json`。游戏中的奶龙角色沿用用户指定素材，并非项目原创形象。
